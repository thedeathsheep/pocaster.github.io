"我想要赛博朋克风格。"

这句话在 AI 创作工具里听起来像是一个清晰的指令。但如果你真的把它作为提示词参数传给模型，得到的结果大概率是：霓虹灯、雨夜、义肢、高楼——赛博朋克小说的刻板印象合集。用户想要的不一定是这些。他们可能只是想要"高对比、冷色调、蓝色和品红的对比光"。这两个描述说的是同一个画面吗？不完全一样。

2026 年 6 月，我做了一份视觉风格调研，想回答一个看似简单的问题：**一个 AI 创作产品的"风格选择器"里，应该放什么选项？**

## 风格不是内容标签

调研开始后不久，我发现了一个问题：团队在列风格清单时，混入了一大批"听起来像风格、实则是内容标签"的词：

`甜宠`、`霸总`、`校园`、`刑侦`、`仙侠`、`年代文`、`都市职场`

这些不是视觉风格。它们是题材分类。可以作为用户选剧的筛选条件，但不能作为画面生成的风格参数。如果把"甜宠"传给模型，它应该输出什么样的画面？"暖调柔光、低对比、浅景深、柔和肤色、亲近构图"——而不是"两个人谈恋爱"。但绝大多数用户和团队都会直接写"甜宠"两个字。

这个问题的本质是：**用户语言和模型语言之间存在一个翻译层，而这个翻译层经常缺失。**

## 母版 + 修饰符：一个可组合的结构

调研结论是：不应该把"视觉风格"做成一个扁平的列表。应该把它拆成可组合的层级结构。

这个结构的设计逻辑是：

- **基础视觉母版**：决定画面媒介和大类观感。8-10 个母版足以覆盖大部分创作场景。
- **修饰符**：决定质感、色彩、光影、镜头语言等具体维度。修饰符可以组合。
- **组合预设**：母版 + 一组修饰符 = 一个可命名的视觉风格预设。

用这个结构，"真人电影感 · 暖调浅景深"就不是一个必须单独录入的"风格"了。它是一组参数的组合：

```json
{
  "visual_base": "真人电影感",
  "color_modifier": "暖调",
  "lens_modifier": "浅景深",
  "lighting_modifier": "柔光",
  "texture_modifier": "轻微胶片颗粒"
}
```

同一套"真人电影感"母版，搭配不同的修饰符，可以生成"真人电影感 · 冷调硬光"、"真人电影感 · 胶片颗粒"、"真人电影感 · 柔雾逆光"——每种组合都对应一套不同的画面产出。

## 命名规范的落地

结构的下一步是命名。如果一个风格预设要在 UI 里展示给用户，它不能是 `visual_base=真人电影感, color_modifier=暖调` 这种工程语言。需要翻译成用户能一眼看懂的名字。

我设计的命名规范是：**媒介/渲染方式 · 主视觉质感**

最终列出的 10 个命名样板：

| 名称 | 结构化对应 |
|------|-----------|
| 真人电影感 · 暖调浅景深 | base=真人, color=暖调, lens=浅景深 |
| 实拍纪实 · 冷峻高对比 | base=实拍, color=冷峻, contrast=高对比 |
| 国漫手绘 · 低饱和胶片 | base=国漫, texture=胶片, saturation=低饱和 |
| 日系淡彩 · 柔光留白 | base=日系, light=柔光, composition=留白 |
| 3D CG · 影视写实 | base=3DCG, style=影视写实 |
| 3D 卡通 · 柔和全局光 | base=3D卡通, light=全局光柔和 |
| 国风水墨 · 写意留白 | base=水墨, style=写意留白 |
| 黏土定格 · 手作质感 | base=黏土, texture=手作 |
| 像素动画 · 复古低清 | base=像素, era=复古 |
| 油画厚涂 · 古典戏剧光 | base=油画, technique=厚涂, light=戏剧光 |

每条预设的背后都是一组可编辑、可调试的结构化参数。用户在 UI 里看到的是"国风水墨 · 写意留白"，传到模型后台的是一组具体的参数组合。这个翻译层就是前面说的"产品要做的事"——把模型能理解的参数翻译成用户能理解的选择。

## 几百种预设不是问题

在做调研前，我担心过一件事：如果每个视觉母版乘以 5 种修饰符，风格预设数量会膨胀到几百种。用户在一个几百种的列表里选择，体验会很差。

但在调研中发现：**几百种预设不是问题，混入内容标签才有问题。** 如果 300 种预设中 200 种是"纯视觉"、100 种是"混入了题材词"，用户真正会困惑的不是那 200 种，而是那 100 种——因为"甜宠"和"刑侦"放在同一个列表里，用户不知道它们的选择逻辑是什么。是选画面风格，还是选剧情类型？

所以正确的做法不是压缩风格数量到"只留 10 个"，而是：

1. 把视觉风格和内容标签拆成两套字段
2. 视觉风格可以有很多，但每条只描述视觉
3. 内容标签用于筛选题材、剧情类型、市场定位
4. 两套字段可以联合使用，但在数据层面不混淆

我当时的研发笔记里写了一句比较直白的话："如果目标是做提示词库而不是做筛选入口，几百种视觉风格预设并不是问题。前提是每个预设仍然只描述视觉，不混入内容题材。"

## 从 v4 到 v6 的迭代

视觉风格调研只是一个起点。后续从 v4 到 v6 的迭代，每一版都在做同一件事：**检查每条预设的视觉边界是否清晰、是否混入了不该混入的内容词。** v4 是基础版 + 安全扩展，v5 做了严格的正负样本分类，v6 替换了一批存在争议的风格并做了原因说明。

每次迭代的变动记录中，"正负面样本列表"是最有用的产出——它比"风格名称列表"更接近真实模型评测：一条预设是不是有效，不是看名字好不好听，而是看它的正样本和负样本是否可区分。如果正负样本之间差距太小，就说明这条预设的视觉边界不够清晰，需要重新定义。

## 收

后来我回头看那篇调研报告里的第一句话：

> "这里的风格只指视觉风格，即用户在画面中能直接看到或感知到的视觉特征组合，不包含题材、剧情类型、人物关系、职业身份、时代背景和故事场景。"

这句话是一个边界定义。定义本身就是答案。

AI 产品的"风格选择器"不是一个列表设计问题，是一个分类学问题。你定义了"什么属于风格、什么不属于"，你的产品边界就有了。
